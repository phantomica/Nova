# Nova · Desktop AI

Nova is a Windows-first desktop assistant for a local [Ollama](https://ollama.com/) model. It stays available as a draggable floating desktop button and in the system tray, and provides a compact chat window, voice input/output, configurable agent skills, and reviewable file proposals.

## Run on Windows

1. Install Node.js 22.12 or newer and [Ollama](https://ollama.com/).
2. Pull a model that supports Ollama chat/tool calling, for example `ollama pull gemma4`.
3. In this folder run `npm install`, then `npm run dev`. This starts the Electron desktop window. The Vite address printed in the terminal is only the renderer development server; opening that address in a regular browser does not provide Electron's desktop bridge.
4. Use the settings button to configure the Ollama URL/model, workspace, allowed applications, and voice preferences.

Use `npm run build` to build the Electron main, preload, and renderer bundles, then `npm start` to run the built app through Electron. For a Windows executable with Nova's own taskbar/process icon, use `npm run package:win` and launch `release/Nova-win32-x64/Nova.exe`; use `npm run make:win` to create a Squirrel Windows installer under `release/make/squirrel.windows/x64`. Development (`npm run dev`) and `npm start` still run under Electron's executable, so Windows may show Electron's process icon there. Forge configures the static Windows executable icon from `resources/icons/nova.ico`, generated from the default Nova SVG theme. This executable icon cannot change when the user changes themes; the running chat-window and tray icons continue to follow the selected accent and theme. Edit `resources/icons/nova-app.svg` and `resources/icons/nova-tray.svg` to customize the artwork, retaining their color placeholders. The packaged app unpacks Sharp's native modules outside the ASAR archive so Electron can load them on Windows.

Nova's chat/taskbar icon is generated from `resources/icons/nova-app.svg`; its notification-area icon is generated from `resources/icons/nova-tray.svg`. The main process rasterizes these templates to PNG and updates the open chat window and tray when settings are saved. The Windows executable icon is a static `.ico` generated from the app SVG's default Nova colors before packaging; regenerate it with `npm run build:app-icon`. Keep all icon assets in `resources/icons` and package them with the app.

After changing Electron's main or preload code, quit any existing Nova windows and stop the old development server before running `npm run dev` again; Vite's renderer hot reload does not reload the preload bridge in an already-running Electron window.

## Current capabilities

- Chat through Ollama's local `/api/chat` endpoint. The model can be changed in Settings.
- Get the current system date and time, the system timezone, the UTC instant, the time in requested IANA timezones, and basic system context (OS/version, locale, uptime, and memory). This information is read-only; timers and alarms are not included.
- Optionally enable read-only Windows diagnostics in Settings to inspect overall CPU/memory use, top processes by CPU/memory, drive capacity and physical-disk activity, and current network-adapter traffic. Diagnostics are disabled by default and have separate category switches under a collapsible settings section. They collect process names/IDs and resource measurements, but not command lines; network readings are not internet speed tests or per-download attribution, and disk activity is not attributed to processes. Nova uses these snapshots as clues rather than proof of a cause.
- Search the web through DuckDuckGo and return result titles, snippets, and links to the model for current-information questions. Nova retries transient connection failures once and reports throttling, anti-bot challenges, or unrecognized provider markup distinctly from an empty result set. Nova can also open a requested HTTP/HTTPS website (for example, `youtube.com`) in the default browser. Search-result text is treated as untrusted reference data.
- Launch configured executables and supported Steam/Spotify links. Executable names resolve through PATH, Windows App Paths, and Start Menu shortcuts; ambiguous or missing matches are reported before launch. Unlisted executables require one-time approval of the exact resolved path when enabled. Nova can send a graceful close request to configured programs when explicitly asked; unlisted programs require one-time approval, and Nova never force-kills a process.
- Open any existing folder path in Windows File Explorer; this does not grant Nova file access. Separately, approved file-access locations control where Nova can browse, read, or propose file changes. Open selected Windows Settings pages and sub-pages, and control Windows playback and audio with ordered command batches, repeated track/volume-key actions, time-based seeking, player status, exact system volume, explicit mute/unmute, output-device selection, and per-app volume. A Desktop app-control master switch and separate launch/close, File Explorer, and Windows Settings switches gate these capabilities; media controls have their own switch.
- “Allow Nova to shut down when asked” is a separate opt-in setting (off by default); when enabled, an explicit request exits Nova only and does not shut down Windows or other applications.
- Configure custom REST API integrations in Settings: set a base URL, optional bearer token, and an explicit list of HTTP methods and endpoint paths. Each API operation independently controls whether confirmation is required, so trusted playback actions can run immediately while sensitive operations can prompt first. Credentials are encrypted with Windows via Electron `safeStorage` and are never included in model prompts. For example, a Spotify integration can use Spotify Web API playback endpoints with a valid bearer token and the required account scopes; OAuth token acquisition/refresh is not built in.
- Agent tool actions are recorded in the conversation with their arguments and result, including program launches, file proposals, searches, and API requests. Confirmable API calls show a review card in chat before they execute.
- When “Agent file access” is enabled, search filenames across the configured workspace and approved locations, or browse one allowed folder at a time in pages of up to 25 entries. Searches can target a named folder such as Downloads, Documents, or Desktop. The Workspace is the first location in File access settings, with a folder picker and “Include subfolders” toggle like other locations; this toggle defaults on to preserve existing behavior. Subfolder access follows each location's toggle; filename search can scan to any depth but stops after 10,000 entries and returns at most 20 matches. `.env` files, dependencies, and symbolic links are excluded. Read matching files and prepare create/edit/delete proposals in those locations; individual reads are capped at 128 KB. Proposals are shown in chat with a diff preview, editable contents, and explicit confirm/deny actions. Confirmation checks that the original file has not changed and the location is still approved.
- “Ask for temporary location access” lets Nova request one specific existing folder outside those locations for the current task only. When a task names such a location, Nova can show the access approval directly without first asking in chat whether it should request access; after approval, the pending search, read, or file proposal is automatically retried. Approval grants that folder and its descendants only; it does not add a permanent location or replace the separate confirmations for file changes and unlisted program launches. A staged file proposal remains reviewable after its task ends, but still requires its own explicit confirmation. This option is off by default.
- Use the multilingual Whisper Small model locally for push-to-talk or an optional wake phrase, and system text-to-speech for spoken replies. Nova begins loading Whisper in the background at startup, so it is ready sooner when you first speak; the first launch downloads about 250 MB to app data. Push-to-talk automatically ends after a pause in speech, and the composer stop button interrupts a response or spoken reply. German is the default transcription language, with other languages and auto-detection available in Settings. Choose Nova's installed TTS voice and adjust its speech rate in Settings, or quickly mute/unmute speech beside the microphone. The Voice setting “Interrupt speech for voice input” stops active TTS when push-to-talk starts or Whisper recognizes the wake phrase.
- Chat and speech bubbles render common Markdown formatting (headings, emphasis, ordered/unordered lists, quotes, rules, and inline/fenced code); speech output strips Markdown syntax before speaking. Voice settings are grouped separately from bubble appearance and dismissal preferences.
- The in-app microphone test requests audio-only access. Recorded speech is resampled and transcribed locally; audio is not sent to an online speech service. Windows microphone privacy settings must permit desktop apps. Wake-word mode processes local audio segments and requires Nova to remain open; its hidden chat renderer keeps audio-segmentation timers active. Say the wake phrase and request together for the quickest response; if you say only the phrase, wait for Nova's prompt before giving the request.
- The floating Nova button can be dragged around the desktop and remembers its location by default. Chat opens beside the floating button by default; enable “Remember chat window position” in Desktop settings to restore its last location instead. Use the chat header’s Clear chat action to reset conversation context; pending approval cards are retained. Choose whether chat size resets whenever it opens, only after Nova restarts (default), or never (in which case its size is restored after a restart). Visible reply bubbles reposition around the floating button. A colored dot shows when Nova is listening, has heard the wake phrase, is recognizing speech, thinking, or speaking. Only thinking appears in an animated status bubble. Reply bubbles grow to fit longer answers where screen space allows, then scroll; Voice settings offer a fixed timeout or keeping them visible through TTS plus the selected 2–60 second delay. The button hides while chat is open so it cannot cover chat controls.
- Pending file proposals appear in the floating speech bubble with an expandable diff and Confirm/Deny actions; choose Edit in chat for the full editing workflow. Confirmed changes still verify that the original file has not changed since the proposal was created.
- Configure Nova in the navigable Settings workspace. Under App theme, optionally rename the app and AI assistant, choose the Nova, Midnight, or Dusk app theme and customize its accent color, or reset appearance to the default. Add approved file-access locations with the native folder picker, edit optional aliases, and remove locations from the list. The program list also has a native executable picker. Settings are stored locally in Electron's user data directory.

## Code map

- `electron/main.ts` owns settings and credentials, Ollama and Whisper requests, desktop windows, and the privileged `tool:run` boundary. Agent implementations are auto-discovered from `electron/features/*.feature.ts`; focused platform helpers (for example app launching or Windows media keys) can live beside them.
- `electron/features/file-access.ts` enforces the workspace/approved-folder boundary for listing, reading, and proposed writes. `electron/features/application-control.ts` owns allowlisted launches and one-time unlisted-launch approvals.
- `electron/preload.ts` exposes the narrow, typed `window.desktop` bridge. Keep Node.js and Electron APIs out of the renderer; new privileged features should have an IPC handler and a matching bridge method.
- `src/ui/App.tsx` coordinates chat history, voice capture, Ollama requests, and action traces. The settings panel, approval, floating-button, and bubble components live in `src/ui/components.tsx`.
- Settings groups can be added as `*.tsx` modules under `src/ui/settings/`; the settings registry discovers them automatically. Each module exports a default `SettingsGroup` descriptor (`id`, `label`, `icon`, and `Component`), whose component receives the current settings draft and a typed `setSetting` callback. New persisted settings still need their shared type, defaults, and main-process validation wired into the settings schema.
- `src/ui/agent-tools.ts` auto-discovers feature-owned schemas and settings gates from `src/ui/agent-tools/*.feature.ts`, then includes request-relevant tool groups to reduce model context. The system prompt adds feature-specific instructions only for the current request. Feature tool handlers are independently auto-discovered in `electron/features/*.feature.ts`; matching names connect schemas to implementations. API schemas are generated only for enabled integrations relevant to the request.
- `electron/features/file-access.ts` provides bounded directory browsing and filename search so file tasks don't dump the contents of every approved folder into the agent context.
- `src/ui/formatting.tsx` contains the supported Markdown renderer, speech-text cleanup, bounded diff generation, and audio resampling helper.
- `src/shared.ts` defines the settings, messages, and bridge types shared by the main and renderer processes; `src/ui/styles.css` contains the interface styling.

### Adding an agent capability

1. Add a `*.feature.ts` schema module under `src/ui/agent-tools/`, exporting `agentToolFeature` with `tools` and an `enabled(settings)` gate.
2. Add a matching `*.feature.ts` implementation under `electron/features/`, exporting a `toolHandlers` map keyed by the schema tool names. The registry discovers these modules automatically; no edits to `App.tsx`, `main.ts`, or a central tool list are needed.
3. Treat model-supplied arguments as untrusted and enforce permissions, allowlists, and confirmation requirements inside the main-process handler. Add settings/types or a preload method only when the feature truly needs those surfaces.
4. Keep user-facing controls and safety behavior documented here, then run `npm run typecheck` and `npm run build`.

## Safety boundaries

The renderer has no direct Node.js access. File operations are available only while “Agent file access” is enabled and are constrained to the configured workspace and approved folder roots; nested access to each root follows its own subfolder toggle. File discovery returns one folder page at a time (25 entries maximum), and filename search returns at most 20 matches after scanning at most 10,000 entries across any directory depth. Program launch is restricted to the allowed-app list unless “Allow one-time approval to launch unlisted programs” is enabled, in which case each unlisted executable/path requires a one-time approval; unlisted launching is unavailable when the setting is off. The corresponding close setting controls one-time-approved graceful close requests for unlisted apps. File Explorer may be opened at any existing folder path and does not grant Nova file access; Windows Settings is restricted to supported pages. Web searches are sent only to DuckDuckGo, and website opening accepts only HTTP/HTTPS URLs. Custom API calls are restricted to the configured integration hosts, methods, and endpoint paths; redirects are blocked, request bodies are capped at 16 KB, and responses at 64 KB. Set operation-specific confirmation for sensitive actions; configured playback actions may run without a prompt. File confirmations are enabled by default. Disabling them in Settings permits file operations to write immediately.
